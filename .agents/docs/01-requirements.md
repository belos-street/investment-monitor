# 01 - 结构化需求工程

> 投资监控浏览器扩展的正式 PRD

---

## 1. 项目概述

### 1.1 定位

| 维度 | 描述 |
|------|------|
| 产品形态 | 浏览器扩展（Browser Extension） |
| 目标浏览器 | Chrome、Edge（Manifest V3） |
| 目标用户 | 价值投资者、定投用户、没时间盯盘的上班族 |
| 核心价值 | 只做提醒，不做交易 |
| 设计理念 | 极简、专注、无干扰 |

### 1.2 一句话描述

> 一个运行在浏览器工具栏的轻量扩展，用户添加关注的 A 股/ETF 标的并配置提醒规则，扩展自动在后台轮询行情数据，条件触发时弹出浏览器通知。

### 1.3 核心设计约束

| 约束 | 说明 |
|------|------|
| 无后端服务 | 所有逻辑在本地运行，不依赖云服务 |
| 不涉及交易 | 只监测行情和指标，不做任何交易操作 |
| 不涉及社交 | 无社区、无新闻推送、无分享功能 |
| 数据本地化 | 持仓和规则存储在本地，不上传云端 |
| 无第三方 UI 库 | 界面使用原生 CSS + Minimal Dark 设计系统实现 |

## 2. 功能模块划分

### 2.1 模块总览

| 模块 | 职责 | 技术实现层 |
|------|------|-----------|
| 持仓管理 | 标的增删、导入导出 | Popup UI + `wxt/storage` |
| 数据监测 | 行情轮询、指标采集 | Service Worker 中 stock-sdk 直连 |
| 规则引擎 | 条件匹配、触发判断 | Service Worker 中运行 |
| 通知服务 | 浏览器通知弹出 | Service Worker + Web Notification API |
| 设置管理 | 更新频率、通知开关 | Popup UI + `wxt/storage` |

### 2.2 优先级划分

**P0（MVP 必须）：**
- A 股/ETF 标的添加（搜索 + 手动输入）
- 实时行情轮询（价格、PE、PB、股息率、涨跌幅）
- 单条件规则配置（价格、PE、PB、股息率、涨跌幅）
- 规则匹配与浏览器通知
- 浏览器工具栏图标常驻 + Popup 主界面
- 持仓和规则本地持久化

**P1（后续迭代）：**
- 组合规则（AND/OR）
- 声音提醒
- 通知历史
- 港股支持
- 插件图标 badge 状态
- Firefox 兼容

## 4. 正常流程

### 4.1 添加标的

```
用户在 Popup 输入代码 → 调用 sdk.search() → 展示结果 → 用户确认
    → 写入 wxt/storage → Popup 刷新列表
```

### 4.2 行情监测循环

```
Service Worker 启动 chrome.alarms（交易时间每 30s）
    → 从 storage 读取持仓和设置
    → 调用 sdk.quotes.cn() 批量查询
    → 更新 storage 中的行情缓存
    → 遍历活跃规则，逐条匹配
    → 匹配成功 → 检查触发策略（单次触发 / 条件复位）
    → 满足触发条件 → 调用 self.registration.showNotification(...)
```

### 4.3 规则触发（单次触发 + 条件复位）

```
当前值 vs 阈值比较
    → 条件从 false 变 true → 触发通知，记录 lastTriggeredAt
    → 条件仍为 true → 跳过（不重复触发）
    → 条件恢复为 false → 标记已复位，下次 true 时可再次触发
```

## 5. 异常流程

| 场景 | 处理方式 |
|------|----------|
| stock-sdk 请求失败 | 静默重试 3 次，间隔递增；全部失败后 badge 变红提示 |
| stock-sdk 返回空数据 | UI 对应字段显示 `-`，不触发规则匹配 |
| 用户输入无效代码 | 搜索结果为空时提示「未找到匹配标的」 |
| YAML 导入格式错误 | 提示「配置文件格式错误」，不写入任何数据 |
| YAML 导入与现有数据冲突 | 覆盖写入（以导入文件为准），导入前提示用户 |
| 通知权限被拒绝 | Popup 状态栏提示「通知权限未开启，请在浏览器设置中开启」 |
| storage 数据损坏/不存在 | 使用空数据初始化，不影响扩展运行 |
| 非交易时间启动 | 不发起数据请求，显示上次缓存数据（如有） |
| Service Worker 被回收 | chrome.alarms 会在下次触发时重新唤醒 |

## 6. 边界场景

| 场景 | 处理方式 |
|------|----------|
| 持仓数量为 0 | Popup 显示空状态提示「暂无持仓，点击添加标的」 |
| 持仓超过 100 个 | 批量查询分批进行（stock-sdk 内置限流），Popup 虚拟滚动 |
| 规则阈值为空/非法 | 表单校验，不允许保存 |
| 同一标的添加两次 | 检查 code + market 唯一性，提示「已存在」 |
| 涨跌幅规则值输入 50% | 合法输入，但二次确认「涨跌幅 50% 较大，确认保存？」 |
| 开机后无网络 | 静默失败，badge 变红提示，有网后自动恢复 |
| Popup 关闭时有未保存规则 | 提示保存确认 |

## 7. 验收标准（DoD）

### 7.1 MVP 完成标准

- [ ] 安装扩展后浏览器工具栏显示图标
- [ ] 点击图标弹出 Popup，显示持仓列表
- [ ] 输入代码可搜索 A 股和 ETF，确认后添加到持仓列表
- [ ] Popup 表格实时显示：代码、名称、实时价、涨跌幅
- [ ] 股票额外显示 PE、PB、股息率；ETF 对应列显示 `-`
- [ ] 交易时间每 30 秒自动刷新行情数据
- [ ] 非交易时间不发起数据请求
- [ ] 可为每个标的配置单条件规则（价格/PE/PB/股息率/涨跌幅）
- [ ] 规则触发时弹出浏览器通知（Service Worker + Web Notification）
- [ ] 同一条件不重复触发（单次触发 + 条件复位策略）
- [ ] 持仓和规则数据持久化到 `wxt/storage`
- [ ] 支持 YAML 格式导出/导入完整配置
- [ ] Popup 打开时间 < 1 秒，Service Worker 启动时间 < 2 秒
- [ ] Chrome 和 Edge 均可正常运行

### 7.2 不在 MVP 范围内（明确排除）

- 组合规则（AND/OR）
- 声音提醒
- 通知历史列表
- 港股行情
- Firefox/Safari 兼容
- 用户账户/登录
- 云端同步
- 深色/浅色主题切换（默认 Minimal Dark）
